Device Overview & Sensors

The Whoop 4.0 is a screenless, subscription-based wearable designed exclusively for continuous biometric monitoring. Released in 2021, it remains Whoop's flagship hardware platform. A Whoop MG (Muscular variant) and Whoop Body line extend placement beyond the wrist.

Onboard Sensors — Whoop 4.0

💓
Photoplethysmography (PPG)
5-LED optical array (green × 3 + red + infrared) for continuous heart rate, SpO₂, and HRV derivation. Green LEDs operate continuously; red/IR activate during sleep for SpO₂.
100 Hz continuous
📐
3-Axis Accelerometer
Detects motion for activity classification, sleep position detection, and respiratory rate derivation (chest rise/fall). Also used to filter motion artifacts from PPG signal.
50 Hz continuous
🌡️
Skin Temperature Sensor
Continuous skin temperature measurement during sleep. Builds a 30-day personal baseline; deviations flag illness, hormonal changes, or poor recovery. New in Whoop 4.0 vs 3.0.
±0.1 °C accuracy
⚡
Galvanic Skin Response (EDA)
Electrodermal activity sensor for stress detection and autonomic nervous system monitoring. Used to improve recovery score accuracy alongside HRV. Not exposed directly via API.
Continuous
🫁
Blood Oxygen (SpO₂)
Overnight oximetry using red/infrared LED ratio across multiple sleep cycles. Average reported as a single post-sleep value. Clinically useful for detecting sleep-disordered breathing.
Overnight sessions only
🔄
3-Axis Gyroscope
Angular velocity sensor for precise movement detection, swim stroke counting, and improving sleep staging by distinguishing position changes from restlessness.
50 Hz continuous

Authentication & OAuth 2.0 Flow

Whoop uses the standard OAuth 2.0 Authorization Code flow. Users explicitly grant your application access. Tokens expire after 1 hour; refresh tokens allow silent renewal for up to ~30 days.

1
Register your application
Visit developer.whoop.com → Create App. Set your redirect URI (must be HTTPS in production). Receive client_id and client_secret. Keep the secret server-side only.
2
Redirect user to Whoop authorization endpoint
GET https://api.prod.whoop.com/oauth/oauth2/auth?client_id=<ID>&redirect_uri=<URI>&response_type=code&scope=read:recovery+read:cycles+read:sleep+read:workout+read:profile&state=<CSRF_TOKEN>
3
User authenticates and grants consent
Whoop's hosted consent screen shows which scopes your app requests. User logs in with their Whoop credentials and clicks "Allow".
4
Receive authorization code at redirect URI
Whoop redirects to https://yourapp.com/callback?code=AUTH_CODE&state=CSRF_TOKEN. Verify state matches to prevent CSRF attacks.
5
Exchange code for access + refresh tokens
POST https://api.prod.whoop.com/oauth/oauth2/token with grant_type=authorization_code, code, client_id, client_secret, redirect_uri. Server-side only.
6
Store tokens securely; implement silent refresh
Access token TTL = 3600s. Use grant_type=refresh_token before expiry. Handle 401 responses by refreshing and retrying the original request. Refresh tokens expire in ~30 days — prompt re-auth when expired.
7
Proxy all API calls through your backend
Include Authorization: Bearer <access_token> on all requests. Never expose tokens or client_secret to frontend code.

Recommended Integration Architecture

Because Whoop data is batch-oriented (post-session aggregates), the correct pattern is a scheduled backend pull with caching — never direct browser-to-Whoop calls.

📱
Whoop 4.0
Syncs via BT to Whoop Cloud
→
⚙️
Your Backend
Cron job pulls Whoop API
every 15 min. Stores in DB.
Handles token refresh.
→
🖥️
Your Frontend
Fetches your API only.
Never touches Whoop directly.

Recommended pull schedule: every 15 minutes during active hours (06:00–23:00 user timezone), every 60 minutes overnight. New recovery/sleep data appears 5–15 minutes after device sync post-waking.

⚠️
Never store client_secret or user tokens in frontend code or environment variables accessible to the browser. Proxy all Whoop API calls through your backend. Token refresh must happen server-side.

Spike Verdict & Recommendations

✅
Go recommendation: Whoop is technically feasible and architecturally sound for integration. The REST API is stable, well-documented, and covers all key health metrics. The primary business constraint is the user subscription requirement ($30/month). We recommend a phased approach: MVP with mock data, then a live pilot with 5–10 opted-in users.
